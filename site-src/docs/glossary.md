# 用語集

VCP のドキュメントで使用する用語をまとめています。概念の詳しい説明は
[コンセプト](concepts/README.md)を参照してください。

---

## VCP の構成要素

**VCP (Virtual Cloud Provider)**
: 複数のクラウドにまたがる計算環境を、統一された方法で構築・運用するためのソフトウェア。

**VCP SDK**
: Jupyter Notebook から VCP を操作するための Python ライブラリ。VC の作成、VC ノードの起動と削除、
  ストレージの割り当てなどを行う。

**VC コントローラ**
: VCP SDK からの要求を受けて、実際にクラウドを操作する中心的なコンポーネント。各機関に 1 つ構築し、
  継続的に運用する。REST API、秘密情報管理、死活監視、メトリクス収集、コンテナレジストリなどの
  機能を持つ複数のコンテナで構成される。

**VC (Virtual Cloud)**
: 複数のクラウドにまたがって構築された、1 つの仮想的なシステム環境。VCP で構築する環境全体を指す
  最も大きな単位。

**UnitGroup**
: 複数の Unit をまとめて扱うための単位。サーバとクライアントのように、性質は異なるが互いに関係を
  持つノード群をひとまとめにする。`compute` と `storage` の 2 つのタイプがある。

**Unit**
: 同質なノードをまとめて扱うための単位。同じ計算資源、同じクラウド、同じ用途のノードが 1 つの Unit
  を構成する。ノード数を増減させる (スケールアウト・スケールイン) 操作の単位でもある。

**VC ノード**
: 実際に確保される個々の計算資源。クラウド上の仮想マシンなどの上で動作し、その中でコンテナが
  実行される。

---

## コンテナ

**ベースコンテナ**
: VCP がすべての VC ノードで共通に起動するコンテナ。VC ノードとしての基本的な機能を提供し、
  VC コントローラとの通信を担う。要件は[ベースコンテナ仕様書](specs/base-container.md)に定義されている。

**アプリケーションコンテナ**
: ベースコンテナの中で動作する、利用者のアプリケーションのためのコンテナ。この入れ子構造
  (Docker in Docker) により、VCP が提供する基盤部分と利用者が自由に構成する部分を分離している。

**アプリケーションテンプレート**
: VCP 上に特定のアプリケーション環境を構築するための手順を Jupyter Notebook として記述したもの。
  [アプリケーションテンプレート](templates/README.md)を参照。

---

## ユーザ種別

**VC 管理者**
: VC コントローラを構築し、運用する役割。ユーザの管理やアクセストークンの発行を行う。

**VC 利用者**
: 構築された VC コントローラを使って、VC ノードを起動しアプリケーションを動かす役割。

**Superuser トークン所有者**
: 特権を持つアクセストークンを保有する利用者。すべての UnitGroup を操作できる。

**owner**
: UnitGroup を作成した利用者。通常の VC 利用者は、自身が owner である UnitGroup のみを操作できる。

## VC コントローラの構成要素

**VCP REST API (occtr)**
: VCP SDK からの要求を受け付ける API。

**秘密情報管理サーバ (OpenBao)**
: クラウドプロバイダの認証情報などを管理する。

**serf**
: 各 VC ノードの死活監視を行う。

**Prometheus / Grafana**
: メトリクスの収集と可視化を行う。VC ノードの CPU・メモリ・GPU などの使用状況を確認できる。

**コンテナレジストリ**
: ベースコンテナやアプリケーションコンテナのイメージを保管する。

**アクセストークン**
: VCP SDK から VC コントローラを操作する際、および秘密情報の読み書きを行う際に使用する認証情報。
  発行方法は[管理操作](vcc/manipulation.md)を参照。

---

## その他

**VPN カタログ**
: 利用可能なクラウドプロバイダとの接続情報をまとめたもの。更新方法は
  [管理操作](vcc/manipulation.md)を参照。

**spec**
: VC ノードを確保する際に指定する、CPU 数やメモリ容量などの要件。VCP がこれを各クラウドの具体的な
  インスタンス種別に対応付ける。指定できる項目は[SDK リファレンス](sdk/README.md)を参照。
