# コンセプト

このページでは、VCP を理解するうえで前提となる考え方と用語を説明します。手順は扱いません。実際に環境を構築する場合は[はじめる](../getting-started/README.md)へ進んでください。

---

## VCP とは

VCP (Virtual Cloud Provider) は、複数のクラウドにまたがる計算環境を、統一された方法で構築・運用するためのソフトウェアです。

クラウドはプロバイダごとに操作方法が異なります。仮想マシンを 1 台起動するだけでも、AWS、Azure、オンプレミスの仮想化基盤ではそれぞれ手順が違い、複数のクラウドを併用すると管理は煩雑になります。VCP はこの差異を吸収し、どのクラウドに対しても同じ書き方で計算資源を確保できるようにします。

VCP の特徴は次の 3 点です。

- **統一的な操作** — クラウドごとの API の違いを VCP が吸収するため、利用者は同じコードで異なるクラウドの資源を扱えます。
- **ネットワークによる囲い込み** — 確保した資源は仮想プライベートネットワークで接続され、複数のクラウドにまたがっていても 1 つのシステムとして扱えます。
- **Notebook による記述** — 構築手順を Jupyter Notebook に記述するため、実行可能な形で手順を残し、再現・共有できます。

---

## 全体の構成

VCP は大きく 3 つの部分から成ります。

```
[ Jupyter Notebook + VCP SDK ]   ← 利用者が操作する
              │  VCP REST API
              ▼
      [ VC コントローラ ]         ← 機関内に構築・運用する
              │
              ▼
[ クラウド上の VC ノード群 ]      ← 実際の計算資源
   AWS / Azure / オンプレミス ...
```

**VCP SDK** は、利用者が計算資源を操作するための Python ライブラリです。Jupyter Notebook から呼び出して使います。

**VC コントローラ** は、SDK からの要求を受けて実際にクラウドを操作する中心的なコンポーネントです。各機関が 1 つ構築し、継続的に運用します。内部にコンテナレジストリや秘密情報管理などの機能を持ちます。

**VC ノード** は、クラウド上に確保された計算資源です。仮想マシンなどの上でコンテナが動作し、その中で利用者のアプリケーションが実行されます。

この構成は、**環境を構築・運用する人 (VC 管理者)** と、**その環境で計算資源を使う人 (VC 利用者)** の 2 つの役割に対応しています。ドキュメントもこの区分に沿って書かれています。

## 基本的な構成要素

VCP SDK が扱う構成要素は、大きい方から順に VC → UnitGroup → Unit → VC ノードという階層になっています。

```
VC (Virtual Cloud)
└── UnitGroup            例: 計算クラスタ
    ├── Unit (master)
    │   └── VC ノード × 1
    └── Unit (worker)
        └── VC ノード × N   ← ここを増減させる
```

### VC (Virtual Cloud)

複数のクラウドにまたがって構築された、1 つの仮想的なシステム環境です。VCP で構築する環境全体を指す、最も大きな単位にあたります。

### UnitGroup

複数の Unit をまとめて扱うための単位です。サーバとクライアントのように、**性質は異なるが互いに関係を持つ**ノード群をひとまとめにします。

UnitGroup には 2 つのタイプがあります。

| タイプ | 内容 |
|---|---|
| `compute` | 仮想マシンなどの計算資源で構成される |
| `storage` | ブロックデバイスなどの記録媒体で構成される |

### Unit

**同質なノード**をまとめて扱うための単位です。同じ計算資源 (CPU・メモリ)、同じクラウド、同じ用途のノードが 1 つの Unit を構成します。

Unit は、それに属するノードの台数を増減させる (スケールアウト・スケールイン) 操作の単位でもあります。たとえば計算クラスタであれば、マスタ用の Unit とワーカ用の Unit を分けておき、負荷に応じてワーカ側の台数だけを変える、といった使い方をします。

### VC ノード

実際に確保される個々の計算資源です。クラウド上の仮想マシンなどの上で動作し、その中でコンテナが実行されます。

## コンテナの構成

VC ノードの上では、2 層のコンテナが動作します。

**ベースコンテナ**は、VCP がすべての VC ノードで共通に起動するコンテナです。VC ノードとしての基本的な機能を提供し、VC コントローラとの通信を担います。ベースコンテナが満たすべき要件は[ベースコンテナ仕様書](../specs/base-container.md)に定義されています。

**アプリケーションコンテナ**は、ベースコンテナの中で動作する、利用者のアプリケーションのためのコンテナです。この入れ子構造 (Docker in Docker) により、VCP が提供する基盤部分と、利用者が自由に構成する部分を分離しています。

アプリケーション環境を一から構築する代わりに、公開されている[アプリケーションテンプレート](../templates/README.md)を利用することもできます。

---

## クラウドプロバイダ

VCP は複数のクラウドプロバイダに対応しており、それぞれプラグインとして実装されています。AWS、Microsoft Azure、オンプレミス環境などが利用でき、1 つの VC の中で複数のプロバイダを併用することもできます。

対応プロバイダの一覧と、それぞれで指定できる項目については [SDK リファレンス](../sdk/README.md)を参照してください。プロバイダによってサポートの状況が異なる場合があります。

---

## 資源の指定方法

計算資源を確保する際は、CPU 数やメモリ容量といった要件を指定します。VCP はこれを各クラウドの具体的なインスタンス種別に対応付けます。プロバイダ固有の名称を直接指定することもできますが、抽象化された指定を使うことで、同じ記述を異なるクラウドで再利用しやすくなります。

指定できる項目の詳細は [SDK リファレンス](../sdk/README.md)を参照してください。
