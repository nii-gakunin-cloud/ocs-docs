# 2. 最初の VC ノードを起動する (VC 利用者向け)

Notebook から VC ノードを 1 台起動し、ログインして動作を確認したうえで削除します。VCP の基本的な操作を
一通り体験できます。

所要時間は 15 分程度です。うち VC ノードの起動に 2〜3 分かかります。

---

## 前提条件

- VC コントローラが構築済みであること ([1. VCP 環境を構築する](setup.md))
- Notebook 環境にログインできること
- VC コントローラのアクセストークンを入手していること
- 使用するクラウドプロバイダの認証情報が VC コントローラに登録されていること

アクセストークンと認証情報の登録は VC 管理者が行います。持っていない場合は VC 管理者に依頼してください。
あわせて、**VC ノードに割り当てられるプライベート IP アドレスの範囲**を VC 管理者に確認しておいてください。

操作は、VC コントローラと一緒に導入された Notebook 環境で行います。VCP SDK が組み込まれているため、
追加の準備は必要ありません。

---

## Notebook の入手

手順は Notebook として用意しています。ダウンロードして、Notebook 環境にアップロードしてください。

- [vcnode.ipynb](vcnode.ipynb)

各セルの説明に沿って上から順に実行すれば、起動から削除まで完了します。設定の方法や注意事項は
Notebook 内に記載しています。

---

## Notebook で行うこと

自分の環境に合わせて指定するのは、クラウドプロバイダ、VC ノードの IP アドレス、仮想マシンのログイン
ユーザ名の 3 つだけです。それ以外の設定は既定のままで動作します。

Notebook は次の 6 つのセクションで構成されています。

| セクション | 内容 |
|---|---|
| 1. 設定 | アクセストークンの入力、SSH 鍵の準備、起動する VC ノードの指定を行います。 |
| 2. VCP SDK の初期化 | VCP SDK を読み込み、VC コントローラに接続します。 |
| 3. 起動処理の定義 | VC ノードを起動する処理を関数として読み込みます。 |
| 4. VC ノードの起動 | UnitGroup を作成し、VC ノードを 1 台起動します。 |
| 5. 動作の確認 | VC ノードに SSH でログインし、ベースコンテナの OS 情報とサービスの稼働状況を表示します。 |
| 6. VC ノードの削除 | 起動した VC ノードを UnitGroup ごと削除します。 |

この Notebook を通して、UnitGroup と Unit を作成して VC ノードを起動する流れと、VC ノード上で動作する
ベースコンテナへのログイン方法を把握できます。

---

## 完了の確認

Notebook を最後まで実行し、VC ノードの起動から削除までが完了すれば、VCP の環境は正しく動作しています。
