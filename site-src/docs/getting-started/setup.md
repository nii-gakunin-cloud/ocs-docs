# 1. VCP 環境を構築する (VC 管理者向け)

VC コントローラを構築し、VCP を利用できる状態にするまでの手順です。機関で 1 回だけ行う作業です。

構築には **VCP ポータブル版**を使用します。このページでは前提条件と全体の流れを説明します。実際のコマンドは、ポータブル版のリポジトリにある[クイックスタート](https://github.com/nii-gakunin-cloud/ocs-vcp-portable/tree/feature/vcc2610#クイックスタート)を参照してください。

---

## 前提条件

構築先のマシンについて、以下を満たしている必要があります。

- **Ubuntu 環境** — クイックスタートの手順は Ubuntu を前提としています。
- **インターネットへの接続** — 各クラウドプロバイダの API にアクセスできる必要があります。
- **外部公開用のホスト名** — Notebook 環境などへのアクセスに使用します。

VC コントローラはコンテナ群として動作しますが、**Docker および Docker Compose が未導入の場合は、クイックスタートで実行するセットアップスクリプトが導入します。**事前に用意する必要はありません。

TLS についてはデフォルトで Nginx による終端を行う設定になっています。`localhost` などで検証する場合は設定の変更が必要です。**変更すべき箇所はクイックスタートに記載があります。**

---

## 事前に用意するもの

| 項目 | 内容 |
|---|---|
| 外部公開用ホスト名 | 設定ファイル内の `NGINX_PROXY_HOST` に指定します。自動では設定されないため、必ず手動で指定してください。 |
| TLS 証明書 | 外部に公開する場合に必要です。検証目的で TLS を使用しない場合は Nginx の設定を変更します。 |
| クラウドプロバイダのアカウントと認証情報 | VC ノードを起動するクラウド (AWS、Azure など) のもの。構築後の初期設定で使用します。 |

---

## 構築の流れ

全体では次の手順を順に実行します。各コマンドの詳細はクイックスタートを参照してください。

| 手順 | 内容 |
|---|---|
| 1. セットアップ | 内部で使用する証明書の作成と環境変数の設定を行います。生成された設定ファイルの内容、特に `NGINX_PROXY_HOST` を確認します。 |
| 2. コンテナの起動 | VC コントローラを構成するコンテナ一式を起動します。ジョブキューの数は環境に合わせて指定します。 |
| 3. 起動の確認 | 想定した数のコンテナが起動していることを確認します。 |
| 4. アクセストークンの発行 | VC コントローラを操作するためのアクセストークンを発行します。 |
| 5. Notebook 環境へのログイン | ブラウザから Notebook 環境にアクセスします。ログインには初期トークンを使用します。 |
| 6. 初期設定 | Notebook 環境に用意されている設定用の Notebook を実行し、アクセストークンを登録して SDK を初期化します。 |

手順 5 以降で使用する **Notebook 環境**は、VC コントローラと一緒に導入されるコンテナです。VCP SDK があらかじめ組み込まれているため、構築後すぐに Notebook から VCP を操作できます。VCP の操作はこの環境で行います。

---

## 完了の確認

手順 6 の初期設定用 Notebook が最後まで実行でき、**SDK から VC コントローラに接続できる状態**になっていれば構築は完了です。

続けて[2. 最初の VC ノードを起動する](first-node.md)を実行し、実際に VC ノードが 1 台起動・削除できることを確認してください。ここまで通れば、環境が正しく動作していると判断できます。

---

## VC コントローラの配置

VC コントローラをどこに置くかによって、いくつかの構成が考えられます。

| 構成 | 概要 |
|---|---|
| 利用機関側に配置 | 機関のネットワーク内にコントローラを置きます。機関のネットワーク運用ポリシーへの影響を小さくしたい場合の選択肢です。 |
| クラウドに配置 | クラウドの仮想セグメント内にコントローラを置きます。機関とクラウド間の接続に VPN を使わない構成も可能になります。 |
| すべてクラウド側に配置 | コントローラとクライアントの両方をクラウド側に置きます。アプリケーション環境をクラウド内で完結させる構成です。 |

このうち、**すべてクラウド側に配置する構成が最もシンプル**です。機関とクラウド間の接続を考慮する必要がなく、構成がクラウド内で完結するため、はじめて構築する場合や動作を確認したい場合はこの構成を推奨します。

構成図を含む詳細は、ポータブル版リポジトリの「VC コントローラ配置例」を参照してください。
