# 1. VCP 環境を構築する (VC 管理者向け)

VC コントローラを構築し、VCP を利用できる状態にするまでの流れです。機関で 1 回だけ行う作業です。

構築には **VCP ポータブル版**を使用します。このページでは、構成の例、前提条件、全体の流れ、完了の確認方法を説明します。実際のコマンドは、ポータブル版のリポジトリにある[インストール手順](https://github.com/nii-gakunin-cloud/ocs-vcp-portable/blob/feature/vcc2610-volume/docs/installation.md)を参照してください。

---

## 構成の例

このページでは、次の構成を例に説明します。はじめて構築する場合や、動作を確認したい場合に適した、最も簡単な構成です。

- クラウドプロバイダとして AWS を使用する
- VC コントローラを、VC ノードと同じ AWS の VPC に置く

VC コントローラと VC ノードが同じネットワークにあるため、VPN を用意する必要がありません。

VC コントローラを機関のネットワーク内に置くこともできます。その場合は、VPN などを使って、VC コントローラと VC ノードがプライベート IP アドレスで相互に通信できるようにします。必要な通信は、インストール手順の「ネットワーク要件」を参照してください。

---

## 前提条件

VC コントローラを動かすマシンは、以下を満たしている必要があります。

- **Ubuntu Server 22.04 LTS または 24.04 LTS** — インストール手順は、この環境で動作が確認されています。
- **10 GB 以上のディスク容量** — 主にコンテナイメージが使用します。
- **インターネットへの接続** — コンテナイメージの取得や、クラウドプロバイダの API へのアクセスに使用します。

Docker と Docker Compose が未導入の場合は、初期セットアップのスクリプトが導入します。事前に用意する必要はありません。

標準の構成では、Notebook 環境などの画面に HTTP でアクセスします。VC コントローラをインターネットから到達できる場所に置く場合は、接続元を制限するか、TLS を設定してください。TLS の設定方法は、インストール手順の「TLS設定」を参照してください。

---

## 事前に用意するもの

例の構成では、AWS 上に次のものを用意します。

| 項目 | 内容 |
|---|---|
| アクセスキー | VC ノードの起動に使用する AWS のアクセスキーとシークレットキーです。構築後の利用セットアップで登録します。 |
| VPC とサブネット | VC コントローラと VC ノードを置きます。VC ノードは起動時にパッケージをインターネットから取得するため、サブネットからインターネットへ接続できるようにします。 |
| VC ノード用のセキュリティグループ | VC コントローラと VC ノードの両方に割り当て、このセキュリティグループ内の通信をすべて許可します。 |
| VC コントローラ用のセキュリティグループ | VC コントローラだけに割り当てます。管理者からの SSH と、管理者・利用者からの 8080 番ポートへの接続を許可します。 |
| VC コントローラ用のインスタンス | 上記のサブネットに、前提条件を満たす Ubuntu のインスタンスを起動します。ディスクは 10 GB 以上にします。 |

リージョン、サブネットの ID とアドレス範囲、VC ノード用のセキュリティグループの ID は、VPN カタログの設定で使用します。

---

## 構築の流れ

全体では次の手順を順に実行します。各手順のコマンドは、インストール手順を参照してください。

| 手順 | 内容 |
|---|---|
| 1. リポジトリの取得 | VC コントローラ用のインスタンスに、ポータブル版のリポジトリを配置します。 |
| 2. 初期セットアップ | セットアップスクリプトを実行します。Docker の導入 (未導入の場合)、環境変数ファイル `.env` の生成、内部通信用の証明書の作成、データ用ディレクトリの作成が行われます。`.env` に設定された IP アドレスが、VC ノードから到達できるプライベート IP アドレスになっていることを確認します。 |
| 3. コンテナの起動 | VC コントローラを構成するコンテナ一式を起動します。ワーカーの数は環境に合わせて指定します。 |
| 4. 起動の確認 | インストール手順の「サービス一覧」にあるコンテナが、すべて起動していることを確認します。 |
| 5. アクセストークンの発行 | VC コントローラを操作するためのアクセストークンを発行します。 |
| 6. VPN カタログの設定 | `config/vpn_catalog.yml` に VC ノードを起動するクラウドの情報を記述し、VC コントローラに反映します。例の構成では、`aws` の `default` に、リージョン、サブネットの ID、VC ノード用のセキュリティグループの ID、サブネットのアドレス範囲を指定します。 |
| 7. Notebook 環境へのログイン | ブラウザから `http://<VC コントローラのアドレス>:8080/jupyter/` にアクセスし、初期トークンでログインします。このときパスワードを設定しておくと、以降はパスワードでログインできます。 |
| 8. 利用セットアップ | Notebook 環境の `work/setup/credential_setup.ipynb` を実行し、アクセストークンの入力、SDK の初期化、AWS の認証情報の登録を行います。 |

手順 7 以降で使用する **Notebook 環境**は、VC コントローラと一緒に導入されるコンテナです。VCP SDK があらかじめ組み込まれているため、構築後すぐに Notebook から VCP を操作できます。

---

## 完了の確認

次の 2 点を満たしていれば、構築は完了です。

- 手順 8 の `credential_setup.ipynb` が最後まで実行でき、SDK から VC コントローラに接続できる
- 手順 6 の VPN カタログが VC コントローラに反映されている。反映された内容は `vcc vpncatalog get` コマンドで確認できます ([vcc コマンド一覧](https://github.com/nii-gakunin-cloud/ocs-vcp-portable/blob/feature/vcc2610-volume/docs/references/cli_commands.md))。

続けて[2. 最初の VC ノードを起動する](first-node.md)を実行し、VC ノードが 1 台起動・削除できることを確認してください。ここまで通れば、環境が正しく動作していると判断できます。

---

## VC 利用者に渡すもの { #for-vc-users }

VC 利用者が[2. 最初の VC ノードを起動する](first-node.md)を実行するには、次の情報が必要です。

| 項目 | 内容 |
|---|---|
| Notebook 環境のログイン情報 | 初回ログイン時に設定したパスワード、または初期トークン |
| アクセストークン | 利用者ごとに VC コントローラのユーザを登録し、そのユーザに対して発行します |
| プライベート IP アドレスの範囲 | VPN カタログに指定したサブネットのアドレス範囲。VC ノードの IP アドレスはこの範囲から選びます |

ユーザの登録とアクセストークンの発行の手順は、ポータブル版の[管理操作](https://github.com/nii-gakunin-cloud/ocs-vcp-portable/blob/feature/vcc2610-volume/docs/manipulation.md)を参照してください。

クラウドプロバイダの認証情報は、アクセストークンごとに保存されます。VC 管理者が手順 8 で登録した認証情報は、別のアクセストークンからは使えません。VC 利用者は、受け取ったアクセストークンを使って、自分で認証情報を登録します。

> **注意**
>
> Notebook 環境は VC コントローラごとに 1 つで、すべての利用者が共用します。ファイルや SSH 鍵も共有されます。
